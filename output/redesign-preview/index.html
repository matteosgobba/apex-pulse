Data, limitations & methodology +

The displayed snapshot comes from the project’s existing dashboard exports, generated on 30 July 2026. It is an archived example, not the current race weekend. This preview does not ingest data, train models or create predictions.

The selected snapshot uses a Random Forest model and an after-FP3 checkpoint. FP1 and FP2 controls show data availability only: no earlier forecast is invented. Circuit outlines use community GeoJSON geometry from Tomislav Bacinger’s f1-circuits archive (MIT license). The moving dots and cursor sparks are illustrative, not telemetry. The countdown checks the public FastF1 calendar every five minutes, when this tab returns and on reconnect. Updated source data replaces the previous calendar, including removals and rescheduling. The current and following seasons are requested automatically; if the next season is not published yet, the interface waits for verified dates. During an outage, it shows the last verified schedule with a visible notice. All times use the visitor’s timezone; it is independent of the archived forecast below. A 30-second zero state marks a scheduled start, then the counter advances to the next session. Five lights indicate proximity at 7 days, 24 hours, 6 hours, 1 hour and 5 minutes; they are not the official starting signal. The eight-second lights demo clearly labels compressed time and automatically returns to the real countdown.

Only 21 of 22 qualifying entrants were forecast. Missing forecasts are not backfilled. Q3 probabilities, uncertainty intervals and private car signals are not available here.
